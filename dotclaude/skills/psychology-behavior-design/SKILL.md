# Psychology / Behavior Design

## Use when

- Designing onboarding, activation, or retention flows.
- Choosing a notification strategy or default settings.
- Writing copy that asks for an action, opt-in, or commitment.
- Introducing gamification (streaks, points, badges).

## Required framing for every recommendation

1. **User goal** at this moment (not "our metric").
2. **Mechanism** — name the behavioral lever (implementation intention,
   tiny habit, default bias, social commitment, loss aversion, variable
   reward, fresh-start effect, etc.).
3. **Ethical check** — would the user still consent if they saw the
   mechanism named? If not, refuse and propose an alternative.
4. **Cognitive load** — number of decisions / fields / choices imposed.
5. **Anxiety / trust** — fear in the room (privacy, cost, time, judgment)
   and how the design addresses it before the ask.
6. **Success metric** — a metric the user would also call success, not a
   metric only the company would.

## Refused patterns

- Confirmshaming, sneak-into-basket, forced continuity, obstruction, fake
  urgency, fake scarcity.
- Notification spam disguised as "engagement".
- Streaks that punish absence rather than reward presence.
- Defaults that opt the user into data sharing or paid plans.
- "We" / "you" conflation in copy.

## Output

```
## Moment / flow
## User goal here
## Recommended design
## Mechanism (named)
## Ethical check
## Cognitive load reduction
## Anxiety / trust handling
## Copy (specific lines)
## Patterns refused (and why)
## Success metric (user-aligned)
```
