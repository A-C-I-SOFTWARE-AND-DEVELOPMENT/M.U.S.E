MEMORY TREE + SELF-EFFICIENT CODER SPEC

Memory Tree inspiration:
OpenHuman uses memory tree and Obsidian-style local vault concepts. Because OpenHuman is GPLv3, do not copy its code into Hermes/Base44. Reimplement the architecture clean-room.

Memory tree clean-room model:
Raw artifact -> canonical note -> validated fact -> memory node -> summary tree -> retrieval packet -> task context

Memory node fields:
- namespace
- source ref
- summary
- confidence
- freshness
- sensitivity
- approval state
- contradiction state
- tags

Namespaces:
- owner/profile
- owner/preferences
- hermes/runtime
- hermes/codebase
- jarvis/strategy
- jarvis/memory
- jarvis/avatar
- jarvis/android-actions
- research/oss
- research/model-routing
- research/natural-language-coding
- failures/lessons
- evaluations

Do not durable-store:
- secrets
- API keys
- raw camera/audio frames
- private credentials
- temporary emotions
- unverified claims

Natural-language coder loop:
1. Interpret request.
2. Classify mode/risk.
3. Localize repo area before editing.
4. Build task packet.
5. Select builder/reviewer/model.
6. Execute in bounded scope.
7. Run tests/checks.
8. Summarize diff.
9. Store lesson only if durable and approved.

Self-efficiency rules:
- No serious code edit without localization first.
- Prefer small scoped diffs.
- Separate builder and reviewer.
- Save failure patterns.
- Reuse known successful packets.
- Stop when acceptance criteria are met.
- Escalate contradictions.

Base44 app role:
- UI to create and review memory nodes.
- UI to generate and inspect task packets.
- UI to show routing decisions and verification gates.
- UI to approve/reject durable memory candidates.
