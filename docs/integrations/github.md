# GitHub integration

Module: `hermes_cli.integrations.github`
Runtime: `hermes_cli.github_publisher`
Skill:   [`skills/github-publisher/SKILL.md`](../../skills/github-publisher/SKILL.md)
Policy:  [`docs/integrations/integration-policy.md`](./integration-policy.md)

## What it does

Turns a set of files into a branch + draft pull request, in three
phases:

1. **Plan.** Compute the branch name (`hermes/job-<id>`), build the
   commit message and PR body, scan files for secrets, build the
   `git push` and `gh pr create` argv. Pure: no git, no network.
2. **Approve.** The operator reviews `explain(plan)` and the
   `publish-plan.md` artifact. Approval is explicit (`approve=True`).
3. **Execute.** The publisher creates the branch, stages files,
   commits, pushes. PR creation is *never* automated — the operator
   runs the printed `gh pr create` command themselves.

## What it never does

- Force-push, reset --hard, clean -f, branch deletes against `main`.
- Reuse a branch. Every job gets its own `hermes/job-<id>` branch.
- Merge a PR. Drafts only; the human merges.
- Stage a file matched by the secret scanner. The whole batch is
  refused if any file flags.

## CLI requirements

| Tool   | Required? | Used for                                |
|--------|-----------|-----------------------------------------|
| `git`  | yes       | branch / stage / commit / push          |
| `gh`   | no        | `gh pr create` argv; falls back to a    |
|        |           | manual command if not present           |

`detect()` reports both.

## Branch naming

`hermes/job-<slugified-job-id>`. Slugs are lowercased, non-alphanumeric
characters collapsed to a single `-`, and capped at 40 chars. The
namespace is reserved for agent-created branches so they're easy to
filter or clean up later.

## Commit message generation

The first line of the commit message becomes the PR title by default.
The body sections are rendered by `prepare_pr_body()`:

```
## Summary
<summary or "Automated change from muse job `<id>`.">

## Changes
- <bullet>
- <bullet>

## Test plan
- [ ] <unchecked checklist>

## Notes
<optional>

## Provenance
- muse job id: `<id>`
- Generated by `hermes_cli.github_publisher`
```

## Approval flow

```python
from hermes_cli.integrations import github

plan = github.plan(
    job_id="kanban-2026-05-23-001",
    files=["src/foo.py", "tests/test_foo.py"],
    commit_message="add foo helper",
    pr_changes=["new function foo()", "tests"],
    pr_test_plan=["pytest tests/test_foo.py -q"],
)
print(github.explain(plan))           # human reviews
# ...operator approves...
github.execute(plan, approve=True)   # branch + push only
# Operator runs `gh pr create ...` themselves to publish the PR.
```

## Rollback

The plan carries `rollback_notes`. The canonical sequence is:

```bash
git push origin --delete <branch>   # remove the remote branch
git checkout -                      # back to your prior branch
git branch -D <branch>              # drop the local branch
```

This is safe because every muse branch is freshly created — there is
nothing on it but the just-pushed commit.

## Validation

- Reviewer opens the draft PR and inspects the diff.
- CI on the PR passes (lint, type-check, tests).
- No secret-shaped strings appear in the diff.
