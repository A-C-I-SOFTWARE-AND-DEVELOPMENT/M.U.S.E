# Upstream sync — Hermes v0.17.0 (v2026.6.19) → M.U.S.E.

**Strategy:** feature-port (Path A), owner-chosen. **Not** a git merge.

## Why not a git merge / rebase

M.U.S.E. and `NousResearch/hermes-agent` **share no common git ancestor**
(`git merge-base HEAD upstream/main` is empty — the fork was imported/squashed,
not branched). Measured divergence at v0.17.0:

| Metric | Value |
|---|---|
| MUSE-only commits | 187 |
| Upstream-only commits | 12,193 |
| Tree difference (HEAD ↔ upstream/main) | **6,864 files, +634k / −587k lines** |

With no merge base there is no 3-way diff, so a `git merge` would treat every
file as a conflict and "resolve" only by **overwriting M.U.S.E. with vanilla
Hermes** — destroying the NEXUS PWA, cockpit, MUSE/JARVIS persona, AOS council,
and all fork-specific work. We therefore **port capabilities**, not history:
each v0.17.0 feature MUSE lacks is brought in as a bounded, validated change
that fits MUSE's architecture and preserves the fork.

`git remote add upstream https://github.com/NousResearch/hermes-agent` is used
locally only as a **reference** to read upstream specs — never to merge.

5. Owner-gate anything that changes default runtime behavior before merge.
