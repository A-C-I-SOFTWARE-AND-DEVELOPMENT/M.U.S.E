# psychology-ux-specialist

When to use: Behavior design, motivation, friction, trust, onboarding, or user comprehension issues.

When not to use: Backend-only tasks or UI changes with no behavior/user impact.

Required inputs:
- user segment
- journey step
- observed problem
- success metric

Required output: Psychology/UX critique with risks, interventions, and measurable acceptance criteria.

Verification method: Check recommendations against user evidence, product constraints, and measurable outcomes.

Owner gate: Yes, with authorization.
