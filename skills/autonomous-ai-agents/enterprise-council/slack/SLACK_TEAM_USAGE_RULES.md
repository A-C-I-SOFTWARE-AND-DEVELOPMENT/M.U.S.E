# Slack Team Usage Rules

1. Use the small default council for daily Slack work.
2. Do not add always-active agents for convenience.
3. Start with a thread summary, requested outcome, risk class, and owner gate check.
4. Summon domain specialists only when their required inputs exist.
5. Route narrow procedures to skills.
6. Route implementation, tests, and docs updates to workers.
7. Workers may report evidence but may not approve strategy, release, legal, or security decisions.
8. Public posts, ad spend, OAuth, account creation, store submission, production deploys, DNS, and main-branch merges require owner authorization.
9. Every Slack decision must cite evidence or explicitly mark an assumption.
10. End each council thread with next action, owner, verification method, and blockers.

Owner gates: Yes, with authorization.
