# muse — Facebook Promo (research-backed)

*Local-first, owner-gated AI operating partner. 200+ models in one chat, self-improving skills, goal-to-PR orchestration. musehq.io*

---

## Strategy at a glance

**Primary objective: Consideration (traffic / trial signups), with a lightweight awareness layer feeding it.**
Category research shows developer-tool spend that converts is split across the funnel, not dumped into cold conversion. The winning pattern for tools like this is: a short vertical video does the awareness lift (build a 50%+-view retargeting pool), then image/carousel creative closes consideration, then a direct "start free" ad harvests high-intent visitors. Because muse is a new category ("AI operating partner," not "another chat wrapper"), the buyer needs one clear demonstration before they'll click — so lead with **consideration** and let the reel seed the top. Cold-to-conversion for an unfamiliar dev tool burns budget; retargeting warm viewers converts far cheaper.

**Target audience + the ONE core insight to lead with**
Audience: developers and technical power users — people who already pay for Cursor, Perplexity Pro, Raycast, or run Ollama/LM Studio locally. They are research-minded, skeptical of hype, privacy-aware, and allergic to feature-dumps.

The ONE angle: **"Your models, your machine, your rules — one partner that ships the work, not just answers."** Every comparable leans on a single ownership idea (Cursor = build faster, Raycast = AI on your OS, Ollama = local/private). muse's ownable wedge is the combination competitors can't claim at once: **local-first + owner-gated + goes from goal all the way to a pull request.** Lead with the outcome (it ships a PR), differentiate on control (local, gated, 200+ models in one place). Do not lead with the model count — that's a supporting proof point, not the hook.

**Recommended primary format + supporting formats (mapped to existing assets)**

| Funnel stage | Format | Asset to use |
|---|---|---|
| Awareness (primary) | 12s vertical reel | **9:16 story/reel** — screen-recording of goal → PR |
| Consideration (primary) | 3-card carousel | **3-card carousel** — problem → how it works → proof |
| Consideration (support) | Single image, mobile feed | **feed 4:5** and **feed 1:1** |
| Conversion / retarget | Single image, direct CTA | **feed 1:1** + **link 1200x630** for link previews |
| Brand / page dressing | Static | **cover** |

Rationale: 9:16 reel is the default high-performing unit (vertical captures materially more engagement and can run notably cheaper per result than static on Reels placements). The carousel carries the "before → mechanism → proof" story the consideration buyer needs. 4:5 is the highest-real-estate feed ratio on mobile and should be the workhorse single image.

## Creative direction

**Reel (12s, 9:16) — the hero asset.** Design sound-off first (assume ~85% watch muted): bold caption overlays carry the story, sound is a bonus. Structure to research:
- **0–3s (hook):** pattern-interrupt on screen — a typed goal ("ship the auth fix") and a hard cut to a PR opening. Front-load this before any logo; aim to stop the scroll in the first three seconds.
- **3–9s (mechanism):** fast screen-capture montage — one chat, model picker flicking through 200+ options, a skill improving itself, actions pausing for the owner's approve/deny. This is the "show, don't tell" demonstration the category rewards.
- **9–12s (CTA):** "Try muse free — musehq.io" with the CTA in the lower third but inside the safe zone (keep the bottom ~20–35% and top ~14% clear of critical text so Meta's UI chrome doesn't cover it).
- Real product UI beats abstract 3D/gradient art — the buyer wants proof it exists and works. Captions on everything.

**Carousel (3 cards):**
1. The pain — the many-tabs, copy-paste-between-models mess.
2. The mechanism — one chat, 200+ models, self-improving skills, local-first.
3. The proof/outcome — a real goal → PR result + free CTA.

**Single images (4:5 / 1:1):** one crisp claim ("From goal to pull request") over a genuine screenshot of the approval-gated PR flow. Minimal chrome. If any frame uses AI-generated visuals, label it — Meta now requires AI-content disclosure and it's a common rejection cause.

## Do / Don't

**Do**
- Show the actual product doing the work (screen-recording of goal → PR) — demonstration outperforms description for dev tools.
- Lead every asset with the outcome and the ownership angle (local-first, owner-gated); make the first line/first 3s earn the click on their own.
- Caption for sound-off and design vertical-first; keep the primary text tight and the CTA inside Meta's safe zone.

**Don't**
- Don't open with the spec sheet ("200+ models, MCP, orchestration…") — feature-dumps are the #1 reason dev-tool ads flop. Specs are proof, not hook.
- Don't over-polish into generic SaaS gloss; this audience trusts raw, real, slightly-unscripted over corporate. Save heavy brand animation for later.
- Don't run only cold-to-conversion — build the warm retargeting pool with the reel first; cold conversion on a brand-new category is the expensive path.
